# Document Checker
Бизнес кейс: AI-агент проверки целевого использования льготных кредитов

REST API сервис для проверки комплектности пакетов документов, предназначенных для заявления в банк в рамках программ льготного кредитования.

Проект выполнен в качестве тестового задания.

---


## Запуск проекта

### 1. Клонировать репозиторий

```bash
git clone <repository_url>

cd document-checker
```

### 2. Создать файл окружения

```bash
cp .env.example .env
```

При необходимости изменить значения.

### 3. Запустить проект

```bash
docker compose up --build
```

При запуске автоматически:

- запускается PostgreSQL;
- применяются миграции Alembic;
- запускается FastAPI.

После запуска API доступно по адресу:

```
http://localhost:8000
```

Swagger:

```
http://localhost:8000/docs
```

## Архитектура решения

```
app/
├── api/
├── core/
├── enums/
├── models/
├── repositories/
├── schemas/
├── services/
├── storage/
└── main.py
```

Проект разделен на несколько слоев:

- **API** — FastAPI endpoints
- **Service** — бизнес-логика проверки
- **Repository** — работа с базой данных
- **Storage** — файловое хранилище
- **Models** — SQLAlchemy ORM
- **Schemas** — Pydantic модели для API

Такое разделение позволяет изолировать бизнес-логику от HTTP и слоя хранения данных и даёт возможность быстрого масштабирования

## Реализованный функционал

### Проверка пакета документов

Поддерживаются две программы:

- `federal`
- `regional`

Проверяется:

- наличие обязательных документов;
- определение типа документа по имени файла;
- допустимый формат файла (`PDF`, `DOCX`, `JPG`, `JPEG`, `PNG`);
- ограничение размера файла (20 МБ);
- предупреждение при невозможности определить тип документа.

---

### REST API

#### POST `/api/checks`

Создает новую проверку.

Принимает:

- пакет документов (`multipart/form-data`)
- тип программы (`federal` или `regional`)

Возвращает:

- идентификатор проверки;
- итоговый статус;
- найденные ошибки и предупреждения;
- список документов;
- время проверки.

---

#### GET `/api/checks`

Возвращает список всех проверок.

---

#### GET `/api/checks/{id}`

Возвращает подробную информацию о конкретной проверке.

---

### Хранение данных

Используется PostgreSQL.

Сохраняются:

- проверки;
- документы;
- результаты проверки (issues).

Файлы документов сохраняются в локальное файловое хранилище:

```
uploads/{check_id}/
```
